# 《深空猫舍》开发与创意工坊发布

核查日期为 2026-11-20。目标游戏为 Steam 正式版《深空当铺：可能是偷的》（Probably Stolen），App ID 为 `4348910`。玩法与遗传规格分别见[玩法核心骨架](玩法核心骨架.md)和[猫猫基因组设计](猫猫基因组设计.md)。

## 开发路线

使用正式版自带的加载器，交付一个 C# 模组。入口实现 `IMod`，按官方范例以 .NET SDK 6 或以上编译到 `netstandard2.1`。猫的个体、遗传、行为和事件结算由模组维护，游戏负责提供物品、窗口、顾客与昼夜事件。首版以官方钩子为基础；需要接触原版交易、货损或声望时，先用测试档验证具体效果。开发者在 Steam 置顶了指南和范例。[开发者置顶帖](https://steamcommunity.com/app/4348910/discussions/0/573805072991083000/) · [官方中文入门与工程示例](https://github.com/dragonpan2/probably-stolen-modding/blob/f1ec77b3021af7124d01478aae58e7a754d43609/README.zh-CN.md)

### 本机基线

0.2.62 的游戏内文本通过 `LocHelper.GetCurrentLocaleCode()` 读取当前游戏语言。Steam 列出简体中文、英语、德语、日语、俄语、法语、西班牙语（西班牙）和波兰语。本机 0.46D 的 `StreamingAssets/aa/StandaloneWindows64` 还带有意大利语、韩语和巴西葡萄牙语的字符串资源。模组提供以上十一种语言，翻译表嵌入 DLL，运行时无需联网。猫在生成时按当时的语言取名，名字随个体保存。[Steam 官方语言表](https://store.steampowered.com/app/4348910/?l=english)

### 0.2.60 测序色块

测序窗口直接显示完整序列。母源统一为珊瑚色，父源统一为青色，0 和 1 的底色深浅一致。出生突变仍用紫框标出。

### 0.2.59 测序性状解读

打开已测序个体时先显示毛长结论。毛长和耳形页将涉及的两对位点按行排列，每行列出双亲传下的值和作用；性别页展示双亲传递的 X 或 Y。完整序列仍可单独查看。旧版个体和实际记录为零次突变的个体显示不同提示。

### 0.2.58 测序结果的亲本来源与突变

母源序列用珊瑚色块，父源序列用青蓝色块。每格保留实际的 0 或 1，本次出生发生翻转的位点另加紫框。A～F 与性染色体共用此规则。幼猫出生时保存翻转位置，测序时随序列归档。初代及旧版出生个体只显示已有来源信息。

### 0.2.57 产后配种间隔

分娩与下次配种之间隔满 1～3 个完整游戏日，由母猫的恢复和耐力基因决定。第 10 天分娩的母猫，最早分别在第 12、13 或 14 天重新参与配种。

### 0.2.56 加工器、产后恢复与购猫预算

猫毛加工器基础价 300，普通难度宠物店标价 450。母猫产后休息 2～5 天，分娩当日记为恢复的第一天，倒计时归零后才可再次受孕。开局和自然繁育均沿用相同的遗传规则。

本地 0.46D 的普通市民买家（`StoreClientListTier.CreateCitizen`）以 145 加 0～50 的均匀整数，再加游戏天数除以 4 的整数部分确定预算。爱猫买家用相同公式，并调用原版 `StoreClient.SetBudget` 结算声望、推荐和店铺吸引力等修正。年龄限制和偏好只影响选猫及报价，多猫交易共用本次来访的预算。

### 0.2.55 物品说明

物品短说明参照本地 0.46D 简体中文物品表（`Item_zh`）的写法。饲料分配器用一句话交代用途，清洁机器人注明启动时机，韧棉纤维说明材料来源和加工产物。猫舍的扩建材料与剩余次数放在动态升级提示中，猫粮热量和加工配方从玩法常量取值。商店与自有猫共用年龄、性别、习性及个体外观说明，领养后另提示双击查看三代血亲。

### 0.2.54 同一只猫的夜间日志

晨报按个体 ID 合并，每只发生事件的猫占一条。外出捕猎、拾荒、外交或找食物的经历写在回窝和钻进容器之前。声望变化跟在对应的外交动作后。只有去向的猫直接写去向，同名个体分别记录。

### 0.2.53 夜行顺序

先结算猫在外捕猎、拾荒或拜访阵营的行动并写入晨报，再移动猫并记录它钻进的容器。阵营声望变化仍显示在对应的拜访记录里。

### 0.2.52 宠物店起始设备

基础猫舍直接放入店内收纳，专用槽预装一台原版喂食机。两只成年猫和 4 份猫粮放在猫窝，机器区（扩建）移出开局清单。

### 0.2.50 宠物店正式开局

宠物店出身领取一个原版「机器区（扩建）」，内放一座基础猫舍。猫窝内有一公一母两只成猫和 4 份猫粮。两只成猫按基础食量合计每天消耗 390 千卡，4 份猫粮共 960 千卡。开局资金沿用原版。喂食器、加工器和扫描仪可在宠物店后续购买。猫舍面板移除调试过夜按钮，猫咪随正常打烊和睡眠结算。

### 0.2.49 踏雪寻梅估价

踏雪寻梅的花色加价由 16 调至 29，介于重点色（28）与雪里拖枪（30）之间。普通白手套仍加 4。两种白爪表现分别估价，每只猫只计其中一项。

### 0.2.48 传统花色与隐性重点色

大块双色加 7，踏雪寻梅加 16，乌云盖雪加 21，重点色加 28，雪里拖枪加 30，挂印拖枪加 34。估价按实际显现的花色计一次。传统花色名称和斑块位置参考《猫苑》，重点色参考暹罗型隐性限制着色。[《猫苑》卷上](https://www.shidianguji.com/book/CADAL02035808/chapter/1l7l4yva9iyhy) · [UC Davis 兽医遗传实验室](https://vgl.ucdavis.edu/test/colorpoint-restriction)

固定种子 48，用模组的初代生成和外观表达代码独立生成 100,000 只猫。大块双色 4,926 只，乌云盖雪 596 只，重点色 2,179 只，踏雪寻梅 258 只，雪里拖枪与挂印拖枪各 109 只。这个分母包括无毛和抑色个体。固定有毛、关闭抑色并关闭突变，双亲各携带一份隐性重点色时，10,000 只子代中 2,563 只表达。相同条件下双亲均为双零时，10,000 只子代全部表达。[成猫与幼猫对照](传统花色与重点色.png)

### 0.2.47 三花立绘

成猫和幼猫沿用早期三花原画的脸部配色、浅色胸毛和四肢斑块。用原模型投影出短毛、长毛和三种耳形的着色参考，游戏中按个体底色、纹路色、白区和花纹种子着色。可用 `python tools/bake-cat-portraits.py --calico-only` 单独重建参考贴图。[格内对照](三花格内对照.png)

### 0.2.46 纯黑与纯白估价

整身纯黑和整身纯白的被毛同档，各加 24 信用点。其他整身纯色加 18。纯色加价每只只计一次。

### 0.2.45 外观遗传、偏好与估价

CFA 对烟色、银渐层和银壳色的描述区分了浅色毛根及毛尖着色的深浅。格内立绘用背脊、两侧和前胸的着色面积近似表现这个差异。三种新花色都能遗传，店里会出现专程找其中某一种的客人。[CFA 毛色描述](https://cfa.org/coat-color-descriptions/) · [格内立绘对照](银系毛色格内对照.png)

**市场依据。** 同一家缅因猫舍的公开标价有雌性黑虎斑 2,300 美元、银虎斑 2,600 美元、烟色 3,000 美元。另一家英短猫舍按金色、银色及稀释色组合标价。这里采用的是特定品种、特定卖家的挂牌偏好，信用点数值按游戏自身经济设定。美国一所收容所对 7,983 只猫的研究观察到毛色与去向的总体关联很弱，因此把专门爱好者的额外报价留在交易环节。[King Coons 价目](https://www.kingcoonsindiana.com/prices) · [Meowmia 价目](https://www.meowmiacattery.com/about) · [收容所研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC7597961/)

**种群依据。** 乌拉圭家猫调查中，非纯种猫以短毛为主（79%）。阿德莱德的 600 只流浪猫样本里，有白斑记录的 573 只中有 285 只带白斑；白斑覆盖和游戏里的深色斑点纹分别统计。该研究也发现某些位点的频率与澳大利亚另一地区有差异。游戏因此分别设置初始来源和父母遗传，不用单一地区的数据推算全球稀有度。[乌拉圭调查](https://www.mdpi.com/2076-2615/13/12/1963) · [阿德莱德调查](https://www.publish.csiro.au/bi/pdf/bi9731215)

### 0.2.44 花色与鼻斑定价

成年基础价 60。无花纹、无特殊斑块的单色被毛加 18，纯白单列加 24。渐层加 5，虎斑、三花、拼色、斑点各加 2。白手套加 4，乌云盖雪加 5，白围兜加 3，重点色加 6，梵花加 10，大块双色加 7。银色、浅棕色各加 28，丁香色、肉桂色、炭灰色各加 8。无毛加 20，长毛加 8，折耳加 12，微折耳加 5，异瞳加 6。鼻斑扣 6。每项独立按实际外观结算；无毛猫不参与被毛花色估价。此表反映店内审美和稀有程度。

### 0.2.43 外观按项计价

成年基础价 60。各可见特征独立累加，保持单独出现时的价格。银色、浅棕色、斑点各加 39；无毛、纯白、折耳、梵花、大块双色各加 26；长毛、微折耳、异瞳、丁香色、肉桂色、炭灰色、渐层、虎斑、三花、拼色、白手套、乌云盖雪、白围兜、重点色各加 13；鼻斑加 1。外观合计后再应用年龄调整，交易时另按买家偏好结算。

### 0.2.42 猫咪估价明细

基础价 60，只按可见外观和年龄调整。各外观明细按实际点数列出，最高档加价归入相应特征，同档并列时归入显示顺序中的第一项；细节总分超过 8 时单列封顶差额。买家偏好仍在交易时单独结算。

### 0.2.41 猫咪估价

成年基础价为 60 信用点。外观每档加 12，细节合计最多加 8。性格按亲人度减易躁度的差值除以 2，取整后限制在 −30 至 +30。捕猎意愿和反应取较低值，20、35、50、65、80 点分别加 0、6、12、18、24。饱腹低于 25 扣 5，低于 55 且至少 25 扣 2。先合计，再应用年龄调整，交易时由买家偏好调整出价。

### 0.2.40 橱窗与买家的年龄偏好

开门生成爱猫人士时，若橱窗有活猫，50% 的机会从中等概率挑一只，按它的年龄吸引想养幼猫、成年猫或稳重老年猫的顾客。其余来客按原有规则生成，仍可能找其他年龄或只看外观、性格。混放时按各年龄实际展示的只数产生影响。顾客提出的年龄条件仍用于筛选交易。

### 0.2.39 猫咪批量出售

猫咪爱好者来访时，把想卖的猫一起放到后区柜台，在原版交易面板按数量出售。每只猫各自检查年龄等硬性条件，按自身报价和买家偏好结算，所有成交共用同一份预算。顾客离场时清除未售猫的临时交易标记和出价调整。

### 0.2.38 晨报与顾客群体文案

晨报记录每只猫的动作，省略夜行所得和新生幼猫的投放位置。有幼猫因空间不足被丢弃时仍会报告数量。实际生效的声望变化接在对应动作后。

「顾客群体」按原版条目格式显示 `猫咪爱好者 (猫咪)`。额外来访的 `猫咪: 随机顾客 (20%)` 列在「预期的普通顾客」下，标题保留原版预计人数。

### 0.2.37 展柜猫咪的顾客预告

「顾客群体」的展柜预告会显示猫咪爱好者。有多只符合条件的猫时，仍显示开门时吸引一名爱猫人士。普通顾客开放后，面板另显示额外抽选普通买家或卖家的 20% 机会。移入和移出猫咪时使用原版面板刷新，同柜商品照常展示各自的原版预告。

### 0.2.36 幼猫出生后投放

新生幼猫优先进入母猫所在的隔间或同一猫舍的另一隔间。猫舍放不下时，幼猫放在会随当铺保存的后区柜台。后区柜台也满时，丢弃超出的个体。次晨日志列出放到后区柜台和丢弃的数量。

### 0.2.35 个体外观立绘

格内、宠物店和遗传图共用按个体计算的正面立绘。底色与主纹叠加白手套、乌云盖雪、白围兜、重点色、梵花、大块双色或斑点虎斑等特殊花色。白斑面积、条纹密度和斑块位置使用基因表达和保存的花纹种子。眉纹、内耳色、鼻色和鼻斑也按个体表达，鼻斑使用独立的种子。

胖瘦、脸颊宽度、口鼻长度、眼睛大小和耳高使用程序模型投影出的位移，和原有的立耳、微折耳、折耳组合。以同一套体表坐标计算花纹后再变形，保留色块和五官在体表上的位置。成猫和幼猫的立绘画布仍分别为 96×192 与 96×48，每格 48 个美术像素。

外观数据分别用 `tools/bake-cat-coat-fields.py`、`tools/bake-cat-face-portraits.py` 和 `tools/bake-cat-shape-fields.py` 从同一个程序模型导出。游戏运行时只读取随模组打包的数据，并根据猫保存的基因生成立绘。

### 0.2.34 耳形立绘

格内和家谱立绘从程序模型的立耳、微折耳、折耳三套轮廓中读取实际表达的耳形。每套轮廓含幼猫、成猫的原有毛长及花纹组合，毛色、肤色及瞳色继续按个体表达着色。旧档猫读取已有基因后即可显示对应耳形。

### 0.2.33 多座猫舍与购猫年龄条件

每座猫舍各自使用喂食器和储粮，窝里的猫和同一猫窝夜游的猫一起配种。每座猫舍的繁育间也分别结算，猫窝和繁育间可逐座扩建。出生时按母猫所在的猫舍和隔间安排幼猫，先尝试她原来的隔间，再尝试同一猫舍内已建好的另一隔间，放不下再到柜台。两个柜台都满时保留待安置的小猫，腾出空间后继续放置。

顾客提出的幼猫、成猫、老年猫条件只决定能否成交。只指定年龄时按猫自己的正常估价出价，外观、性格等其他偏好仍参与当次交易调整。

每份猫粮占 2×2 格，提供 240 千卡，基础价 32 信用点。宠物店测试开局给 8 份，4 份在猫窝，另 4 份和设备一起放在「机器区（扩建）」。调试生成器的出料网格改为 8×6，仍可容纳 12 份。按新档验证。

### 0.2.13 猫毛加工、价格与命中区

猫粮、猫舍和猫毛加工器按实际占格响应悬停、点击和拖动。晨报以猫的名字描述换窝、外出所得和产仔，领取位置随收获提示展示。

调价后的基础值为猫粮 32、猫毛 4、猫舍 250、猫毛加工器 400 信用点。成年猫估价以 72 为基数，按可见外观分普通、少见、稀有和极稀有四档。同年龄下稀有档压过性格、捕猎和照料引起的差价。幼猫加 40%，老年猫减 35%，宠物店按估价的 1.5 倍出售成年猫。调试道具和猫尸价值为 0。

0.46D 原版价格按本机数据核对。「一小口食物」140 千卡、15 信用点，「一口食物」275 千卡、30 信用点，「生肉（小）」550 千卡、65 信用点。按 240 千卡折算为 26–28 信用点，猫粮加上单格直接投喂的溢价后为 32。一对猫每天基础消耗 390 千卡，折合约 52 信用点，最低遗传食量下一对也约需 42 信用点。普通幼猫最高估价约 113，爱猫顾客每天一次 25% 来访机会，每次收一只，经营收益还要计入养成和等客人的时间。

猫舍价格与原版鼠笼相同。猫毛加工器与原版自动屠宰机同为 400，高于基础搅拌机和熔炉的 200。10 份猫毛基础值 40，织物原版基础值 65。每批的 4 千焦参照原版小型制瓶机和净水机的单次耗电。标准电池初始 100 千焦，可加工 25 批。

猫毛优先掉在猫所在的容器，满了转入后区或店内收纳，仍放不下则保留记录。独立 3×3 加工器有电时在夜里收毛，每 10 份猫毛和 4 千焦生成 1 份原版韧棉织物。猫舍移除加工器扩展槽。新测试开局用原版电池替换清洁机器人。本版按新档验收。

### 0.2.12 夜行收获投放

在原版晨间存档前，把夜行收获放在可见的后区柜台。那里放不下时改放店内收纳。两处都满时保留待投放记录，读档、开门和后续过夜时再试。晨报标明物品已放到的区域。旧档仍在待投放队列里的收获沿用同一流程。

### 0.2.11 猫窝夜游与繁育间

繁育间里的猫会留在隔间内，只同隔间里的适龄猫配种。成年与老年猫可以从猫窝自行换容器，自行外出的猫跨夜仍属于猫窝的配种组。位置随原版库存保存，猫窝外出状态随个体保存。玩家重新摆放猫后按实际住处分组。喂食仍在实际所在的隔间结算。

### 0.2.10 猫粮热量调整

每格一份猫粮改为 240 千卡，约等于猫 1.23 天的基础消耗。直接喂食和加工为混合饲料使用同一个热量值。旧档还没加工的猫粮在载入时更新，已加工的混合饲料继续按库存记录结算。

### 0.2.9 猫咪交互与照料

猫咪用整块占格接收悬停、拖动与双击，母猫的详情和遗传图都显示怀孕进度。测序保留每只猫首次得到的 0/1 位串，界面省去日期和基因规则版本。用原版蓝色标签打印机改名，详情标题显示猫的名字，名字与亲缘记录随个体保存。蓝色标签打印机加入宠物店开局测试物资，已有测试档有空位时补发。

成年基础估价 150 信用点，幼猫在同性状成年价上加 40%，老年猫减 35%。猫咪爱好者按来访需求收猫，猫物品使用买家匹配而无需通用品类。移除刀具对猫的动作，活猫放进原版垃圾桶会触发遗弃，保留家谱。自然死亡留下的猫尸仍可走清洁服务。

换算原版鼠类的 3 倍，猫的每日基础食量为 195 千卡，饱腹容量为 1500 千卡。短毛猫每天掉 1 份，长毛猫每天掉 2 份，无毛猫不掉毛。猫毛统一为每份 3 信用点。夜间成年和老年猫有机会移动到允许放猫的店内容器，幼猫留在原处。

### 0.2.8 猫舍调试工具

猫窝下方的「调试：过一夜」会走原版打烊和睡眠流程，结算整家店的夜间服务、猫舍和游戏日，再保存次日状态。余额不足时会停在原版夜间服务界面，可在那里调整服务。营业中需先处理必须接待的顾客。

宠物店开局的「机器区（扩建）」改发一台猫粮生成器。双击打开，点击「生成猫粮」填满最多 12 个空出料格，每格一份，取走后可以再生成。已有测试档会补发一台，曾经领取的原版增压器仍属于该存档。

### 0.2.7 繁育、遗传图与机器调整

母猫的基因影响窝产倾向，每次受孕独立抽取 1–8 只并记入存档。活猫按年龄、可见外观、性格、捕猎和饱腹度估价。收来的猫毛按掉毛时的已表达毛长和花色定价，每份 3–7 信用点。无来源记录的猫毛按 3 信用点计。

双击猫打开三代遗传图。立绘卡片可以点击，母系与父系连线使用不同颜色，右侧按外观、性格、习性和状态排版。已取得的测序结果另以双色 0/1 位块展示。

猫舍提示沿用 0.46D 鼠笼 `AnimalCage.CreateTooltip` 的材料、剩余升级次数和满尺寸提示。猫窝从 8×4 至 8×10，韧棉织物先建造 6×4 繁育间，再扩建至 6×10。猫毛加工器的出料仓只供玩家取出成品。

新建「宠物店」时，测试机器区另发原版「超科技涡轮增压器」（`turbo_booster_hypertech`）。其原版 `CURRENT_CHARGE_TAG` 初始为 1500，增压一次消耗 15 点，物件详情会显示 100 次存储充能。

### 0.2.6 猫毛拖动修正

猫毛在原版库存中使用整格鼠标命中，透明边缘也能拾起。实际拖放仍由原版库存检查。程序生成的猫咪立绘保留可读像素，让原版鼠标命中检测能读取透明度。

### 0.2.5 分配器投喂调整

猫粮在进料格中显示自身的图标。选择「加工饲料」或开启原版自动加工后，原料被消耗，每份向原版「其他食物」混合料提供 550 千卡。升级后的旧档也可以加工仍留在进料格的整份猫粮。已混合的库存继续沿用其原版记录。

装有分配器的猫窝按原版规则从低于 75 点饱腹的猫中结算投喂。每只猫按分配器设置的目标值补足，饲料不足时只吃到现有存量。55 点是整份猫粮直接给猫吃时的恢复量。未装分配器的隔间仍可提供松散的食物。

### 0.2.4 试玩调整

开局设备和材料仍放进原版「机器区（扩建）」。新的测试物资清单不发背包。原版收纳和开局天赋照常工作。

猫粮放进猫舍的喂食器后保留独立名字和贴图。饱食低于 55 时，猫会优先吃专用猫粮，每份恢复 55 点饱食。已经加工成通用混合饲料的旧猫粮继续以原有热量供给。猫毛加工器的「加工」按钮每次将 10 件猫毛变为 1 件韧棉织物，也可按原来的模式设为夜间自动加工。

金属锭和韧棉织物可以拖到猫舍上，悬停可查两处面积和已升级的次数。悬停猫可读基础状态与距下一阶段的天数。遗传图由双击打开，已表达性状用文字，测序位串按染色体与亲本来源排列。剪线钳可对成年和老年活猫使用，刀具走原版动物物件的使用手势。

#### 物品贴图导出规则

新制物品贴图按每格 64 个美术像素导出 RGBA PNG，从未缩小的原稿去底后采样，保留轮廓半透明像素。猫粮和猫毛导出 64×64，2×2 的加工器导出 128×128，4×3 的猫舍导出 256×192。物品仍用明确定义的格子形状。资源加载时在 `InventoryArt.cs` 注册外形和 400 PPU，使用双线性采样，在原生 16 像素一格的大小下显示。验收检查画布尺寸、透明边界和贴图占格。

### 0.2.3 试玩调整

新建「宠物店」后，原版「机器区（扩建）」内直接放猫舍和测试物资。为给单件物品留格，这版的开局数量为 7 块金属锭、8 份韧棉织物、12 份猫毛和 24 份猫粮。两处能各升六次，材料各有余量。猫舍内先放两只成猫和基础猫粮。设备、工具和其余试用材料可在机器区内直接取用。

喂食器显示在猫窝左侧，猫窝和繁育间分别用金属锭、韧棉织物对猫舍使用来扩建。两处满级时保留手里的材料。猫粮是专用饲料，饥饿时优先取用，每份恢复 55 点饱食，也可用原版喂食器加工。猫粮和猫毛每格一件，已有存档的旧堆叠有空格后逐件拆开。

猫舍、猫粮、猫毛和加工器使用各自的物品图。加工器类别为机器，进料仓可容纳 40 件猫毛，出料仓可平放 12 件韧棉织物。清洁机器人由 0.46D 原版 `vacuum_robot` 工厂生成并使用原版贴图。活猫交易标签分为猫崽子和成猫，估价按年龄、性状和饱腹结算。

### 0.2.2 临时开局测试包

新建「宠物店」出身时，测试装备直接放入原版主收纳，放不下的转入后区。开局发一件原版「机器区（扩建）」（`machine_bay_ext`）、清洁机器人、喂食器、猫毛加工器、基因扫描仪、剪线钳、厨房切肉刀和夜行用小背包。材料为 10 块金属锭、10 份韧棉织物、30 份猫毛及额外 36 份猫粮，另加 500 信用点。两处空间都可用这些材料扩到 10 行。

物资按新周目发一次，店内暂时摆不下的份数留待下次重试。已有 `0.2.1` 测试箱的旧档会把现存物品转入原版收纳，在转完后清理空箱。`0.2.1` 的启动日志显示，0.46D 在主菜单注册王尔德服务时会提前构造 `PlayerStore`，导致初始化失败。`0.2.2` 改在进入周目后注册服务。黑市清洁兑换沿用原版解锁与服务条件。

### 0.2.0 本地测试版

此版本面向 Steam 构建 `26525552`，清单目标为 `0.46D`。Release 编译无警告和错误。离线检查通过八种窝产量、旧档单崽任务、成年亲本和子代 ID，以及旧猫舍宽度迁移。游戏中的界面、拖放和夜间结果留给本地试玩。

新建「宠物店」出身后，两只开局成猫住在 8×4 普通空间。选中手里的金属锭对猫舍使用，或把韧棉织物拖进「韧棉装配」槽。两处都向下逐行扩至 10 行。当前测试参数为每次装配消耗一份韧棉织物，成年合格猫同住时普通空间与繁育隔间的每夜受孕几率分别为 35% 和 55%。双击猫打开个体详情和三代图。发明家的原版基因扫描仪开着时，查看实际持有的活猫可保存该个体的 0/1 序列。

### 0.1.8 测试版

工程位于 `src/DeepSpaceCattery/`。选择「宠物店」出身时，开局的成年公母猫都在猫舍里，另有 12 份猫粮。猫舍本体占 3×2 格，内部初始为 6×4 格，可摆下三只 2×4 格成猫。幼猫占 2×1 格，混放由原生库存按实际空间判定。消耗 1 个金属锭可以原位扩格，首次扩至 8×4 格。已安装的设备和猫的位置保留，内部尺寸随周目保存。

双击猫舍打开原生容器。主格可放自有的猫、原版吸尘器和食物。旁边有原版喂食器专用槽及「加工饲料」按钮，喂食器的加工由原版执行。夜间在猫舍里的饥饿猫优先从喂食器取用饲料，再尝试吃主格中可直接食用的食品。「照料与育种」菜单可查看立绘、位置和饱腹度，也可以用备存猫粮手动喂食。

每只短毛猫每天掉 1 份毛，长毛猫掉 3 份，无毛猫不掉毛。原版吸尘器放在猫舍主格时，夜间回收店内积累的猫毛。在「照料与育种」的「猫毛」区可查看散落和已收集数量，并用 10 份已收集的猫毛合成 1 份原版「韧棉织物」（`kotton_fabric`）。成品放置成功后才扣除猫毛。

在旧面板安排育种后，系统暂时收起双亲道具。两天后，幼猫先尝试放入猫舍，再安排双亲回到店内。猫舍放不下时，调用原版动物生产的 `GraphUtils.EmporiumTryAdd` 处理溢出，具体落点由游戏决定。猫的道具标签保存个体 ID，年龄、家谱和基因保存在周目记录中。幼猫长大后换成 2×4 格的成年道具。猫粮保存在猫舍记录里。

旧版养猫周目第一次载入时，会尝试把店里的原有猫放进猫舍，沿用个体 ID 和基因。找到 3×2 格并放入新猫舍后才移除旧的 1 格终端。背包、后区和展示柜都放不下时，仍可用旧终端管理。清出空间后再次打开管理界面即可重试。普通出身沿用原版开局。

宠物店的地点卡为 296×168，抵达后的场景背景为 960×540。宠物店专精使用独立的 19×19 图标，3×2 格猫舍使用 48×32 的背包精灵。猫咪立绘保留每格 48 像素和轮廓抗锯齿，成猫为 96×192，幼猫为 96×48，实际占格分别为 2×4 和 2×1。游戏从程序模型的材质图集计算毛色或肤色、斑毛色和双眼颜色，并按毛长与主花纹选择轮廓及纹样。营业陪伴、自主夜行、其他首猫入口、猫咪交易、基因测序和工具处置将在后续迭代接入。

## 从空工程到本地加载

1. 在项目根目录执行 `./tools/build-mod.ps1`。可用 `-GameDirectory` 指定游戏路径，或设环境变量 `PROBABLY_STOLEN_DIRECTORY`。需要指定 SDK 时传入 `-Dotnet`。脚本编译 Release 并输出到 `dist/DeepSpaceCattery/`。
2. 将输出目录放到 `<游戏根目录>\Mods\DeepSpaceCattery\`。包根直接放 `manifest.xml`、`DeepSpaceCattery.dll`，图片放 `Textures/Items/`。工坊上传使用同一目录布局。
3. 清单中的固定模组 ID 为 `deep_space_cattery`。更新时递增 `ModVersion`，更新实际验证过的游戏版本。当前清单使用 `<Capabilities />`。
4. 游戏主菜单进入 Mods，启用并重启。在独立周目选择「宠物店」，双击猫舍核对两只开局成猫。现有测试包的网格和操作以 [0.1.8 测试版](#018-测试版)为准。新版按下方实机验收表走纵向扩容、自然繁育、三代遗传图和猫毛加工。
5. 另开普通出身，核对开局未赠猫。切回宠物店周目，核对猫名单、猫粮和任务与各自进度一致。用旧版领过猫的测试档验证原个体和基因可读。调试时可在游戏根目录放空的 `dev.txt` 并重启，使用 F8 控制台执行 `mod-scan deep_space_cattery`。检查权限、遗漏 DLL、拒绝项和将弃用的调用。发行包只带本模组 DLL 与运行资源。[官方入门](https://github.com/dragonpan2/probably-stolen-modding/blob/f1ec77b3021af7124d01478aae58e7a754d43609/README.zh-CN.md) · [调试与扫描](https://github.com/dragonpan2/probably-stolen-modding/blob/f1ec77b3021af7124d01478aae58e7a754d43609/ModdingGuide.md#checking-before-you-publish)

**版本窗口。** 开发者公告计划在 **2026-12-10** 完整合入模组安全更新。按当前指南，届时声明 `files` 或 `network` 的工坊模组需要开发者验证，部分旧能力会被拒绝。猫猫玩法目前没有外部联网或通用文件访问需求。发布时重查公告和 API 变更，并用目标构建重新扫描。[游戏官方公告](https://steamcommunity.com/app/4348910/workshop/?l=schinese) · [官方扫描规则](https://github.com/dragonpan2/probably-stolen-modding/blob/f1ec77b3021af7124d01478aae58e7a754d43609/ModdingGuide.md#capabilities-and-the-scanner)

## Steam 创意工坊发布与更新

开发者指定用 **SteamCMD** 和拥有正式版游戏的 Steam 账号发布；游戏内 Mods 菜单用于启用、管理和订阅测试。以下路径为将来打包时的示例。[官方上传说明](https://github.com/dragonpan2/probably-stolen-modding/blob/f1ec77b3021af7124d01478aae58e7a754d43609/ModdingGuide.md#publishing-with-steamcmd) · [Valve SteamCMD](https://developer.valvesoftware.com/wiki/SteamCMD)

1. 将已通过本地测试的包放到独立的 `contentfolder`，确认其根直接包含 manifest。准备小于 1 MB 的预览图。VDF 放在内容目录外，控制谁可看、上传哪一版、更新哪一条目。
2. 首传 VDF 可采用下例。文件路径按实际产物替换，`publishedfileid = 0` 建新条目，`visibility = 2` 先仅自己可见。

```text
"workshopitem"
{
    "appid"           "4348910"
    "publishedfileid" "0"
    "contentfolder"   "D:/ModRelease/DeepSpaceCattery"
    "previewfile"     "D:/ModRelease/DeepSpaceCattery/preview.png"
    "visibility"      "2"
    "title"           "深空猫舍"
    "description"     "在当铺养猫、追踪家谱，看它自己挑地方趴着，猜它明早会带回什么。"
    "changenote"      "首次订阅安装测试"
}
```

3. 运行 `steamcmd +login <Steam账号名> +workshop_build_item "D:/ModRelease/cats.vdf" +quit`，按 Steam 提示完成登录及首次创意工坊协议。成功后 SteamCMD 会将条目 ID 写回 VDF，保留这份文件。
4. 用发布账号订阅隐藏条目，暂时把本地同 ID 开发包移出游戏的 Mods 目录（本地包优先），待 Steam 下载完成。游戏 Mods 中确认 Steam 图标、版本、中文名和封面。启用并重启，从宠物店出身开始，走完照料、育种、跨夜和读档。再上传一次隐藏更新，确认同一条目能更新，原有猫的身份和基因能正确恢复。
5. 页面写明支持的游戏构建、前置依赖、操作入口、存档影响和经测试的停用步骤。验收后保留条目 ID，将 VDF 的 `visibility` 改为 `0` 公开；以后递增 manifest 的 `ModVersion`、填写 `changenote`，沿用同一 VDF 上传。玩家继续使用原订阅。[游戏创意工坊](https://steamcommunity.com/app/4348910/workshop/?l=schinese)

| 个体图标与占格 | 并排放一只左蓝右绿、长毛白手套的猫和一只短毛拼色猫，检查移动、读档后左右眼、爪尖白斑和拼色位置是否仍对应各自个体。用无毛猫核对肤色。幼猫显示正面趴姿，占 2 格宽、1 格高。长到成年后切换为正面坐姿，占 2 格宽、4 格高，并沿用该猫的外观表达值 |

| 衰老与交易 | 验证老年猫不会进入新的配对。分别出售猫崽子与成猫，验证对应客人接受标签、成交金额和个体去向 |
